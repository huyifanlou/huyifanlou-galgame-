# 45 · 公共室内实体占位与出口净空修正

作者（2026-10-27）：

> 这几个内部空间内部各实体占位不合理，重新布局一下。出口处有东西遮挡，
> 是不是之前空间没变化的布局没删干净影响了重新布局，删干净之后再重新构造

## 一、先确认：不是旧布局重复构建

排查结果：

- `InteriorBuilder.Build(w.Root)` 全局只有 **1 处调用**（`InteriorManager.Init`）。
- 场景里没有序列化的 `Interior_*` 根节点；旧室内是运行时生成，不会留在场景。
- 旧的 `Library / Restaurant / Supermarket` 函数已在 docs/44 的改造中从
  `InteriorBuilder.Shops.cs` 删除，现只剩共享工具函数；三间与食堂都由
  `InteriorBuilder.PublicInteriors.cs` 重新构造。

所以遮挡不是「旧布局没删干净」，而是**新布局把中央展示台/生鲜岛/绿植放在了
出口中轴线上**。这轮把实体挪开，并新增自动校验。

## 二、出口净空自动校验

`Interior` 新增：

```csharp
public float ClearX1, ClearX2, ClearZ1, ClearZ2;
public bool HasClear => ...
```

`InteriorBuilder.Validate` 会检查所有非墙碰撞盒是否与净空区重叠，重叠即打印：

```

```

## 三、实体挪位

1. **图书馆**：入口中央新书展示台从 `x=0` 移到 `x=-4.5`（靠西侧），
   中央通道与南门直通；新书桌仍在门东侧，不压中轴。
2. **超市**：中央生鲜岛从 `x=-2.0` 移到 `x=-4.8`，生鲜吊牌跟随；
   购物篮从 ±2.2 移到 ±3.3，购物车从 3.0/3.6 移到 4.2/4.8，门内中轴清空。
3. **食堂**：门口绿植从 `x=0.4,z=8.2` 移到东南角 `x=13.2,z=8.0`；
   调料/水吧从 `x=-2.2` 移到 `x=-4.8`；西侧四人桌从 `x=-2.5` 移到 `x=-5.0`。
4. **餐厅**：回看门口确认迎宾台/等位沙发都在门两侧，门内净空本来就够，
   无需移动。

## 五、教训

- 大空间里「中央展示台/中央生鲜岛」最容易压住门的视线和动线；
  入口到出口的中轴必须作为一级约束，不能等做完再目测。
- 出口净空要写进校验器，而不是靠截图记忆；净空区应包括门内侧数米，不只是门口。
- 怀疑「旧布局没删干净」时先查构建调用次数、场景序列化对象和旧函数定义，
  再判断是残留还是新摆放问题——这次是后者。
