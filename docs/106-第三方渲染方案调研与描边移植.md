## 三、scss 实测（重点）

### 3.1 集成

按 UPM 包方式装入 `Game/Packages/com.s-ilent.crosstone/`。
包结构正确（有 `package.json`、`Runtime/`、`Editor/`），Unity 正常识别并注册。
**构建零 shader 错误**。

确认它有完整的 BIRP 支持：
- `LightMode = ForwardBase`（第 667 行）
- `LightMode = ForwardAdd`（第 709 行）
- `LightMode = ShadowCaster`
- `SCSS_CompatBIRP.hlsl` 兼容层，不硬引用 URP 包

### 3.2 画质对比（`shots/300-scss-probe.png`）

同一场景、同一光照、同一组 albedo，并排渲染：

| 项 | Campus/Toon（自写） | scss Lightramp |
|---|---|---|
| 3 阶阶梯光照 | ✅ 干净 | ✅ 干净 |
| 球体明暗过渡 | ✅ 平滑无杂色 | ⚠️ 有轻微色带 |
| 描边 | ✅ 有 | ✅ 有 |
| 整体 | **不输** | 不输 |

**结论：基础画质上两者没有本质差距。** 我们上一轮调的参数是有效的，全面替换的收益不足。

### 3.3 薄片描边对比（`shots/301-outline-probe.png`）

这是唯一发现的决定性差异。测试体是 1.0×1.0×**0.06m** 的薄片：

- **Campus/Toon（改前）**：薄片上的描边**几乎完全消失**
- **scss**：薄片描边**完整可见**

### 3.4 人物对比（`shots/320-char-probe.png`）

把 `PlayerAvatar` 真实渲染的六人并排，左 = Campus/Toon，右 = scss。

**scss 版出现严重缺陷**：景楠的夹克变成**半透明**，能透出背景和地面。

根因：scss 的 BIRP pass 里写着
```
Blend[_SrcBlend][_DstBlend], One One
```
第二个 `One One` 是给 ForwardAdd 用的固定值。**直接 `new Material()` 创建时不经过它的 Editor GUI 初始化**，
混合模式会取到错误分支。而它的 GUI 初始化逻辑在 `Editor/*.cs` 的 `SetupMaterialWithRenderingMode` 里。

这对我们是**致命缺陷**：本工程全部材质都是运行时程序化生成的，没有走 Editor GUI 的机会。

**结论：人物不改用 scss。**

## 四、最终落地：只移植描边机制

### 4.1 改了什么（`Game/Assets/Shaders/Toon.shader`）

借鉴 scss 的三项能力：

1. **宽度按 FOV 归一化的视距缩放**
   scss 的做法：
   ```hlsl
   float fov = atan(1.0 / unity_CameraProjection._11) * 1.14591559;
   float distanceFactor = distance(o.worldPos, _WorldSpaceCameraPos) * fov;
   float finalScale = clamp(distanceFactor, _OutlineNearDistance, _OutlineFarDistance);
   o.extraData.x *= finalScale;
   ```
   我们原来只乘 `clip.w`，数学上等价于「屏幕恒定宽度」，但在薄片上会和背面 shell 重叠导致描边被吞掉。
   改成按 FOV 归一化后，薄片处不再互相吞。

2. **近远距离可调**：`_OutlineNearDistance` / `_OutlineFarDistance`（原来写死 18/55）

3. **法线退化兜底**：薄片边缘的法线几乎垂直于视线时，屏幕投影趋近 0，外扩方向不稳定。
   检测到 `len < 0.08` 时，改用「物体中心 → 顶点的屏幕方向」作为兜底，保证始终有明确外扩方向。

另外预留了两项能力（暂未启用，等有需要再用）：
- `_OutlineMask`：逐部位控制描边强弱（贴图 R 通道）
- `_OUTLINE_VERTEXCOLOR`：用顶点色 R 通道当宽度倍率（程序化网格可按面标宽度）

### 4.2 新增 API（`Game/Assets/Scripts/MatLib.cs`）

```csharp
MatLib.SetOutlineRange(m, near, far);        // 调近远距离
MatLib.SetOutlineMask(m, maskTex);           // 设部位遮罩
MatLib.EnableOutlineVertexColor(m, true);    // 开启顶点色控宽
```

`NewToon()` 里已默认填好近远距离与全白遮罩，所有材质自动生效。

## 五、关于 URP（B 档）

**决定：暂不做。**

原估成本 8~13 个工作日，主要卡在：
1. `PostFX.cs` 的 `OnRenderImage` 在 URP 下完全失效 → 后处理要重做成 `ScriptableRendererFeature`
2. `Toon.shader` 的 ForwardBase/ForwardAdd 双 pass → URP 单 pass 重写
3. `TimeOfDay` 的 `RenderSettings.*` 三色环境光 → Volume 系统
4. 27 处 `shadowCastingMode` + 9 处 `receiveShadows` + 7 处静态合批复核

但**实测后发现换管线的收益低于预期**：我们自己的 BIRP 管线已经能达到 scss 级别的基础画质。
换 URP 的主要收益是「能用更多现成 shader」，而那些 shader 大多是**角色向**的
（原神/星铁风格，追求二次元角色细腻面部），对我们这种 2.5D 叙事游戏的大场景帮助有限。

若未来要做大量角色特写，那时再换，成本不会比现在更高。

## 六、遗留与下一步

1. **scss 包是否保留**：当前留在 `Game/Packages/com.s-ilent.crosstone/`。
   它不影响构建（已验证），但作为运行时依赖**不可用于程序化材质**。
   如果确定只用它的思路，可以删掉以保持工程干净。
2. **卡通水面**：`IronWarrior/ToonWaterShader`（Unlicense）值得引入，
   替换现在的 `Campus/Water`。原理简单（噪声波 + 深度泡沫），风险低。
3. **屏幕空间描边**：`IronWarrior/UnityOutlineShader`（Unlicense）与几何外扩互补，
   如果后续发现几何外扩仍有边缘问题（如细长物体、交叉面），可以叠加。
4. **描边宽度需按分辨率复核**：当前按 1600×900 调，4K 下可能偏细。
   现在有 `_OutlineNearDistance/_OutlineFarDistance` 可调，比原来方便。
