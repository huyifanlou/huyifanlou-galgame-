# 144 · 桌面快捷方式旧图标引用与品牌残留清理

2026-11-16。作者反馈桌面图标仍旧，要求清理以前的 Logo 和图标残留。

## 根因与修正

上轮只更新并验证了 exe 内嵌图标，遗漏桌面快捷方式的独立图标引用。`C:/Users/ASUSA/Desktop/他山之石.lnk` 目标确实是当前 Campus.exe，但 IconLocation 仍指定旧短路径 `.../UNITY~1/Game/Build/icon.ico,0`，所以桌面不会跟随 exe 图标变化。

Bootstrap 现在同时生成 `Game/Build/Win/jingying-profile.ico`，含16、24、32、48、64、96、128、256八档，以当前 Assets/icon.png 为唯一图像源。桌面快捷方式已更新目标、工作目录和 IconLocation，图标明确指向新 ICO，不再依赖旧的 icon.ico。

新增 `tools/branding/refresh-game-shortcuts.ps1`，只匹配本游戏桌面/公共桌面/任务栏快捷方式，可重新绑定及刷新；`-VerifyOnly` 只回读验证。使用 SHChangeNotify 与 ie4uinit 刷新，不强制重启 Explorer、不删除其他软件缓存。

## 实际删除

- 旧部署图标 `Game/Build/icon.ico`。
- `Scenario/brand` 旧图标、开场 Logo 生成页面与废弃概念资源。
- `tools/archive/143-branding` 中上一轮保留的旧 Logo 图片、meta 与旧图标备份。
- Bootstrap 内失效的 SetupIntroTextures 导入代码。

删除前记录并校验绝对路径清单，限上述旧品牌目录与旧图标，共45文件、5个空目录。批量变量删除被工具拒绝后，改为逐一显式文件路径的可核对删除，已全部完成；清单见 removal-manifest.json。新头像原图/提示、当前 Assets/icon.png 和历史验证文档/截图保留。

旧 IntroScreen 仅是已有 UI 的 Live=false 兼容接口，没有动画、绘制、旧资源读取或等待。Unity 引擎自身启动标识仍按其授权规则处理，不当作本项目旧开场资产删除。

## 验证

- build.log：129MB Windows 构建成功，无脚本/Shader异常，ICO八档生成通过。
- shortcuts.json 记录桌面快捷方式原、新图标引用，保存后再次回读校验通过。
- 从 Windows Shell 实际解析桌面 `.lnk` 得到 desktop-shell-icon.png，已目视确认是新镜荧头像带快捷方式箭头，而非只验证 exe。
- 原 icon.ico、Scenario/brand、143旧品牌档案目录均不存在；活动工程/品牌脚本无旧导入函数与图标引用。

完成后从修好的桌面快捷方式正常启动游戏供作者查看，保持运行。未提交、未推送。
