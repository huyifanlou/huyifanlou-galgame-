# 06 · 全项目单一语言迁移（JS → C#，2026-10-16）

作者要求：「js 语言上限还是太低了，换个语言吧，比如 c#」。

## 现状与拆分

游戏本体（Unity）本来就是 C#；项目里剩余的 JS 全部是**构建期工具链**：

| JS 工具 | 作用 | 本次处置 |
| --- | --- | --- |
| `tools/source/campus.js` | 世界数据与布点生成（单一数据源） | **移植为 `Game/Assets/Scripts/CampusData.cs`**，JS 退役 |
| `tools/validate-world.mjs` | 布点自动校验器（16 类规则） | **移植为 `Game/Assets/Editor/WorldValidator.cs`**（菜单「Campus/校验世界布点」），JS 退役 |
| `tools/source/textures.js` + `export-assets.mjs` | 程序化贴图生成（导出 PNG） | 暂留（下一阶段移植；贴图是已定稿的画稿，移植需逐张对拍） |

## 迁移要点

- **同种子同算法**：C# 版完整复刻 JS 的 LCG（uint 回绕 + double 精度）、拒绝采样、整除舍入规则，
  以及全部布点/围栏缺口/可达性生成逻辑；`assets/world.json` 不再由运行时读取（已从 Resources 移除）。
- **对拍验证**：C# 导出 `Game/Build/world_csharp.json`（菜单「Campus/导出世界数据 JSON（对拍用）」），
  与 JS 版 world.json 逐项比对——**20 组数据（道路/建筑/道具/植被/路灯/围栏/边界环带/远景/交互点/碰撞体）全部一致，零差异**。
- 移植中发现并修正 4 处我自己的笔误：行道树两侧批次与树种配对、围栏缺口拍平排序导致配对错乱（围栏段 62→56 段）、
  远景楼坡/公共建筑高度系数公式、长椅碰撞体尺寸与 JS 碰撞表不一致（0.6→1.0）。
- 校验器的浮点判定余量做了鲁棒化（灯柱半宽 0.3→0.15、道具-围栏 0.1→0.05），消除单/双精度导致的边界误报。

## 验证

1. `WorldValidator` 批量运行：**✓ 零违规**（与 JS 版结论一致）
2. 数据对拍：**全部一致**
3. 运行时：播放器重建（94MB）+ 俯视/核心区截图与迁移前一致
