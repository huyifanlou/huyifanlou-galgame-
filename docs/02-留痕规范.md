# 留痕规范 v0.1（对应评分：过程可复现性与演进链路 25%）

## 1. Git 提交规范

- 每完成**一个功能模块**或**一次与 AI 的核心对话落地**即提交一次；严禁大包提交
- 提交信息格式：`<type>(<scope>): <描述> (prompt-<编号>)`
  - type：`feat` / `fix` / `docs` / `refactor` / `test` / `chore`
  - 示例：`feat(日程系统): 时间推进与体力消耗闭环 (prompt-012)`
  - 示例：`fix(对话): 流式输出中断后状态未重置（引导 AI 排查 3 轮定位）(prompt-019)`
- 提交前自检：`git status` 无多余文件；密钥与大文件不入库

## 2. Prompt 归档规范（`prompts/` 目录）

每次与 AI 的核心交互**当天**归档为一个文件：`prompts/NNN-YYYY-MM-DD-主题.md`

模板：

```markdown
# prompt-NNN · 主题（日期）

## 目标（我的一句话意图）
## 我的 Prompt（原文，可多轮）
## AI 产出（摘要 + 关键决策 / 建议）
## 我的修正与追问（如何引导 AI 修 Bug 或调整方向）
## 结果（截图引用 / 关联提交号 / 可运行证据）
```

- 一个「核心功能迭代」= 多轮 prompt 组成的完整链；**至少保留 3 条完整链**（迭代 1/2/3）
- 建议每天收工前 5 分钟归档当日对话，防止事后回忆失真

## 3. 录屏规范（对应演示视频「AI 协同过程展示」≥2 分钟）

- 每次开发会话开始即开录（OBS 或 Win+G），全量保留原始素材
- 必须覆盖两种镜头：
  1. ZCode 中「输入 Prompt → AI 生成 → 运行验证/修错」的完整过程
  2. 游戏内「功能从无到有」的对比片段
- 每次迭代完成当天，补录 30 秒小结（口头回顾本迭代的意图控制策略，可选但加分）
- 原始录屏放本机 `recordings/`（已被 gitignore，不入库）；剪辑成 5-8 分钟视频后随提交物提交

## 4. 截图规范

- 关键节点截图存 `docs/screenshots/`，命名：`NN-日期-内容.png`
- 每次迭代完成截「功能运行图」；Bug 修复保留「修复前 / 修复后」对比

## 5. 素材版权规范（对应违纪红线第 3 条：抄袭 / 未声明引用）

- AI 生成素材：记录工具 + 生成 Prompt + 日期，统一登记在 `docs/素材记录.md`
- 第三方素材（如 CC0 音效）：记录来源链接 + 许可协议，宁缺毋滥
- 严禁使用未声明的他人作品；一切引用必须在技术文档中声明
