# 85 · 共面闪面（柜台 / 沙发 / 椅子）与帧率节奏、地图 GC 抖动

作者反馈三件事：**奶茶店柜台还在闪、柜台上的东西超出台面**；**宿舍楼寝室的沙发都闪**；**帧率是不是低了，一卡一卡**。

## 一、奶茶店柜台闪面

`BarCounter` 的台面板底边正好落在柜体顶面上（都是 y=1.05）→ 两个共平面一直在 z-fighting。改成台面板下沉 2cm 压进柜体（1.03~1.09），共面消失，台缘厚度不变。

## 二、柜台上实体超出台面

吧台面板的范围是 z 2.12~3.08，而：

- 展示柜整体在 z 2.81~3.49 → **前缘超出台面 0.41m**，看着像挂在吧台外面；
- 封口机在 z 1.975~2.325 → 后半截压在前缘外。

两者都收进台面范围内（展示柜中心 z=2.60、封口机 z=2.45），柜内两排甜点仍然朝顾客面（+Z）露出。

## 三、沙发 / 椅子 / 桌子：同材质共面（按类一起改）

`Sofa` 的坐垫、扶手、靠背三件用的是**同一材质**，而坐标正好撞在一起：坐垫与扶手都是深 0.95（z=±0.475 共面）、坐垫/靠背/扶手的外侧都到 x=±len/2（共面）、靠背面与坐垫背面只差 5mm → 宿舍每间寝室的沙发边都在闪。

改法是把各件深度互相错开 ≥2cm：坐垫内缩（0.86 深、比扶手窄）、扶手外凸（0.94 深）、靠背变窄后移（宽 len−0.24、z −0.44~−0.28）、底座再内缩（0.78 深）。共用函数一次改到，**奶茶店/餐厅/食堂/图书馆/礼堂后台/宿舍所有沙发同时生效**。

按同一标准排查了另外两个共用家具函数：

| 函数 | 共面处 | 改法 |
| --- | --- | --- |
| `Chair` | 靠背与坐面同宽（x=±0.23）、背面齐平（z=−0.23） | 靠背窄 4cm、后沿内缩 1cm |
| `Table` | 四条腿的顶面正好等于底板底面（y=h−0.08） | 腿加长 4cm 伸进底板 |

## 四、"一卡一卡"：不是掉帧，是帧节奏 + GC 抖动

先实测（`-fpslog`，每 300 帧打一次平均）：

```
[Perf] 近 300 帧平均 59.9 FPS   ×8 段，全程 59.9~60.0
```

**平均帧率是满的**，所以"卡"来自两处节奏问题：

1. **高刷屏上的帧节奏**：默认「锁 60 且关垂直同步」（`WorldBuilder.Start`）。在 144/165Hz 屏上，16.67ms 的帧不能整除刷新周期，每帧被显示 2 或 3 个刷新周期 → 画面本身稳定 60，但看起来一顿一顿。
   → 加运行时切换键 **F10**，三档循环：`锁定 60（默认）→ 垂直同步（高刷屏更顺，约 55~60）→ 不锁帧（跟随刷新率）`，切换时有 toast 提示，HUD 操作行加了「F10 帧率模式」。作者可以直接在自己屏幕上试出最顺的一档。
2. **地图 OnGUI 每帧分配**：`Minimap.OnGUI` 里每次都 `new GUIStyle`，放大地图时还要**每个地标一个样式**（约 40 个 × 每帧两遍 GUI 事件）→ 每秒上千个托管对象，Gen0 GC 周期性抖动。
   → 样式全部缓存成字段（只在 `_large` 切换时重建），地标标签列表改成复用 + `Clear()`。剩下的 `new Rect/Color/Vector2` 都是值类型，不产生垃圾。
