# 25 · 树木净距最终过滤、河边长椅、启动性能与崩溃风险

作者反馈：神社前还有树挡住/卡进建模；河边长椅浮空；树的排布与建筑间距反复出问题；启动时 CPU/GPU 占用异常高，偶尔闪退。

## 一、树木与建筑：改为“最终过滤”
之前靠生成时的保留区逐条排除，但不同批次的树（点景树、行道树、河畔树、散布、公园树）容易漏掉。现在在 `TownData.Build()` 末尾统一过滤一遍，以下位置的树**一律剔除**：
- 神社前庭与参道口：x 67~91、z -72~-42（12m×15m 的大留空，含原先挡在殿前的松树）。
- 任意建筑轮廓外扩 **2.6m**（树冠半径级别，避免树冠压墙/穿檐）。
- 主角家同口径。
- 三座桥面及两端引桥（宽/2+3m、长/2+3m）。
过滤后的树才写入 `W.TREES`，不再依赖生成顺序。实拍（06:00）：[town-shrine-clear.png](img/town-shrine-clear.png)

## 二、河边长椅
- 旧数据里 (-30, -2.5) 这把椅子算下来落在河道内（距中心线 7.4m < 8m），所以浮在水面上。
- 现改为**按河道中心线定位**：`z = RiverZ(x) ± 15.8`，放在滨河步道外缘，南岸朝北、北岸朝南（面朝河）。
- 公园环塘的 8 张长椅仍面朝水面；广场/站前/住宅街的长椅按朝向道路/广场摆放。
- 近景确认椅腿落地：[town-bench.png](img/town-bench.png)

## 三、性能与崩溃
- **锁帧**：`Application.targetFrameRate = 60` + `vSyncCount = 1`（此前未锁帧，实测 700+ FPS，CPU/GPU 长期满载）。
- **路灯点光源按距离开启**：每 0.25s 只启用相机 38m 内的灯，其余关闭（约 90 盏 → 常驻 8~14 盏），大幅减少前向渲染的光照 pass。
- **移除每栋建筑的夜景立面贴图 + 自发光贴图生成**：黄昏时不再一次性生成 36 张 2048 级夜景贴图与遮罩（内存峰值与卡顿的主要来源）；夜间窗户效果保留为“四格亮窗发光片”。
- 阴影距离 90m、相机远裁 200m。
- 预计启动/运行的内存与 GPU 压力显著下降；若仍遇到闪退，请把 `Player.log` 发我，我按具体报错继续查。

实拍（夜景仍保留路灯与亮窗）：[town-night-capped.png](img/town-night-capped.png)
