# 88 · 路灯朝向与间距量化复核

作者要求：**检查路灯方向是否正确，两盏灯之间的间距是否合理**。这次不靠肉眼看截图，改成量化核对。

## 一、做法：导出当前世界 + 脚本核对

新增 `WorldValidator.DumpTownJsonBatch`（菜单「Campus/导出当前世界 JSON」）→ `Game/Build/world_town.json`，导出的是**跑完全部生成流程之后**的数据（含"让开车行道外推""正门 2.8m 内删除"这些后处理），不是源码里的理想点位。脚本按两条规则核对：

1. **朝向**：灯杆模型的手臂沿**局部 +X**（灯头、灯罩、地面光斑都在 +X 侧），所以世界方向 = (cos r, −sin r)。凡"站在某条街肩线上"（到路中心线的距离 = 半路宽 + 0.8m，容差 0.6m）的灯，手臂必须垂直指向该街中心线，点积 < 0.3 判为朝向错。
2. **间距**：按路、按侧统计同侧相邻灯的间距；再统计全世界两两最近距离（找"双灯"）。

## 三、修法

- 主街、中央街改成**显式点位表**（不再等距循环），桥两端各留一盏：主街 z = −84/−64/−44/−24/−4/20/36/52/72/90，中央街 z = −88/−68/−48/−28/−10/14/32/52/72/92；
- 新增**最小间距去重**（3m 以内算重复，保留先登记的干路/街坊路灯）—— 路口两侧各一盏（4~5m）是正常做法，不误删；
- 新增**最后统一"对灯臂"**：凡落在某条街肩线上的灯，按所在街重算朝向（南北向路：西侧 0、东侧 π；东西向路：北侧 −π/2、南侧 +π/2）。这样以后改路宽、改灯位都不会再把手臂写歪，被外推到街肩上的滨河灯也自动跟着对；
- 补车站路 2 盏（东侧朝西，20m）、公园联络路 2 盏（西侧朝东，18m）；
- 住宅北街在门缝里补两盏（x=−48、−29），把 37m 空档压到 19m 以内。

## 五、有意保留的"不装灯"

- **夏日祭参道、神社石阶**：由石灯笼与提灯串照明（docs/82 的设计），不放现代路灯；
- **桥面**：主街跨河段的灯在桥头两侧（桥宽只有 11m，灯杆立在桥面上会挡路）；
- **公园内部 4 盏、广场 4 盏**：景观灯，不参与街道间距统计。
