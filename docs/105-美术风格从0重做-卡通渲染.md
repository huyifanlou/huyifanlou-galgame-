# 103 · 美术风格从 0 重做：写实 → 卡通渲染（Cel Shading）

> 写于 2026-11-10。本轮是**推倒重来**，不是迭代：
> 作者判定「整个城镇效果不好，忘掉最开始的游戏美术风格，从 0 开始」。
> 保留：剧本与对话系统、玩法与键位、人物建模（作者明确要求「人物建模暂时保留」）。
> 重做：渲染管线、材质体系、贴图体系、世界几何造型、光照与天空、后处理。

## 一、为什么推翻（上一版到底差在哪）

上一版是「写实 Standard + SSAO + ACES 色调映射 + 程序化天空盒」，
但世界几何是**程序化生成的方块体块**、人物是**《我的世界》风方块人**、树是**体素叶块**。

三者互相冲突，最后什么都不是：

| 冲突 | 具体表现 |
|---|---|
| 方块几何 × 写实光照 | 写实 PBR 让平墙出现大面积灰渐变，方盒子读起来像「未贴图的占位体」 |
| 方块人 × 写实场景 | 人物像被丢进实景照片里的贴纸 |
| 体素树 × 写实材质 | 樱花树冠是 0.2m 立方体拼的，远看是一团噪点 |
| ACES 色调映射 | 把本来就不多的颜色压得更平，画面发灰 |

**根因**：写实渲染要求高精度几何与真实材质，程序化生成达不到；
而卡通渲染**恰恰是为低精度几何设计的**——它用色阶、描边、大色块把形体「读」出来。
所以方向不是「把写实做得更好」，而是**换成与程序化几何匹配的画风**。

作者选的路线：**卡通渲染 3D（Cel Shading）**，保留 3D 与玩法，视觉语汇全面换成二次元卡通。

## 二、技术架构：三个支点

本轮改造的关键判断是：**全工程只有一个材质出口**（`MatLib`）和**一个贴图出口**（`TextureLibrary`），
所以只要把这两个出口换掉，整个世界、室内、人物的画风会**同时**变过来——这是能在一轮内完成的原因。

```
                    ┌─────────────────────────────┐
   世界几何 ────────▶│  MatLib（唯一材质出口）      │
   室内几何 ────────▶│  全部返回 Campus/Toon 材质   │──▶ 卡通渲染
   人物几何 ────────▶│                             │
                    └──────────────┬──────────────┘
                                   │ 取贴图
                    ┌──────────────▼──────────────┐
                    │  TextureLibrary（贴图出口）  │
                    │  全部改为平涂大色块          │
                    └─────────────────────────────┘
```

### 2.1 新着色器 `Campus/Toon`

`Game/Assets/Shaders/Toon.shader`。要点：

- **3 阶 ramp 光照**：`ndotl` 经 `ToonStep()` 量化为阶梯，这是卡通的骨架
- **冷调暗面**：暗面不是变黑，而是乘 `_ShadowTint`（默认冷紫 `0.52,0.55,0.78`）——
  「亮面暖、暗面冷」是卡通渲染最基本的语汇
- **反向外扩描边**：`Cull Front` + 视空间法线外扩 + **乘 `clip.w` 补偿**，屏幕空间宽度恒定
- **距离淡出**：18m 内满强度、55m 外完全淡出（`frag_o` 里按视距 lerp 到场景色）。
  不加这个，远景密集物体（树/栏杆）的描边会糊成一片黑
- **硬边高光**：`step(0.5, pow(...))` 而非 smooth，卡通高光是「一块」，不是「一片」
- **边缘光**：勾轮廓体积，受光面更明显
- **自发光**：走 `_EMISSION` 关键字 + `_EmissionColor`，与 `TimeOfDay` 的夜间开关兼容

### 2.2 新后处理 `Campus/ToonPostFX`

`Game/Assets/Shaders/ToonPostFX.shader` + `Scripts/PostFX.cs`。

卡通渲染的后处理和写实**是反着来的**：

| 上一版（写实） | 本轮（卡通） | 原因 |
|---|---|---|
| SSAO | **删除** | 暗面已由 ramp 表达，再加 AO 会让暗部变脏 |
| ACES 色调映射 | **删除** | ACES 压平颜色，卡通要鲜艳通透 |
| 移轴景深 | 默认关闭 | 卡通不需要微缩感 |
| — | **色调分离**（新增） | 轻度量化出赛璐珞质感，`Posterize` 默认 0.35 |
| 泛光 | 保留但重调 | 白天 0.18、夜里 **0.12**（降下来！见下） |

### 2.3 贴图体系：写实噪点 → 平涂大色块

`Scripts/TextureLibrary.cs` 整体重写。这是**第二重要**的改动，只换着色器不换贴图会得到
「卡通光照 + 写实噪点」的最丑组合（本轮第一张对比图就是这个症状）。

卡通贴图原则：
- 平涂大色块，一个面只有 1~3 个色阶
- 硬边分隔（窗框/墙裙/分格线用纯色实线，不做羽化）
- 高饱和、明度高（**暗部交给 shader 统一压，贴图本身不画暗**）
- 不用随机噪点做材质感，改用有规律的图案（砖缝、瓦垄、条纹）

建筑立面（`Building()`）是本轮最重要的贴图：平涂墙色 + 硬边窗框 + 纯色窗玻璃
（白天天空蓝 / 夜里暖黄，只有两态）+ 硬边墙裙 + 楼层分格线。
上一版画的玻璃反射渐变、雨痕、脏污**全部删除**。

### 2.4 几何造型：方块 → 卡通形

`Scripts/MeshFactory.cs` 新增三个卡通专用网格：

- **`ToonCanopy(radius, ...)`** —— 低多边形球（10×7 段）+ 低频扰动，替掉所有方块树冠
- **`HipRoof(w, d, h, overhang)`** —— 四坡屋顶，厚实 + 檐口外挑 0.85m（写实版是 0.24m 薄板）
- **`BevelBox(size, bevel)`** —— 倒角盒（6 主面 + 12 棱面 + 8 角），卡通家具/道具主力形状

世界侧改动：
- 普通树：从「三层叶簇方块」改成「一根干 + 主冠 + 副冠 + 底部暗冠」四团圆球
- 樱花：从「《我的世界》体素树（0.2m 叶块拼的）」改成「一根干 + 主冠 + 四团侧冠 + 顶冠」，
  粉色调亮调纯（`CherryMat` 从「leaves 贴图 × 粉色 tint」改成**纯色 + 粗描边**——
  贴图是深绿底，相乘后粉色被压成脏褐色，这就是第一版樱花像枯树的根因）
- 巨樱：从「体素巨树」改成「粗圆柱干 + 4 条主枝 + 1 主冠 + 6 环绕副冠 + 2 顶冠」
- 屋顶：从「两片薄板斜搭 + 三角山墙」改成整块 `HipRoof` + 檐口封板 + 屋脊压条
- 长椅：加倒角、木色提亮（写实深褐在卡通光照下发黑）

### 2.5 光照与天空

`Scripts/TimeOfDay.cs` 关键改动：

- **天空**：删掉程序化天空盒（大气散射渐变会把画面拉回写实），改回**平涂渐变穹顶**（双穹交叉淡化）
- **光照比例**：白天 太阳 1.15 / 环境 0.42（写实版是 0.95/0.28，太平，糊成一片）
- **卡通全局量**：`_ToonAmbient` / `_ToonSunPower` 由 `MatLib.SetGlobals()` 每帧写入
- **夜景**：深蓝环境 `(0.10, 0.13, 0.27)` + 暖黄路灯，靠**对比**而不是整体提亮

## 三、踩过的坑（下一轮别再踩）

### 坑 1：只换着色器不换贴图 = 最丑的组合

第一版只改了 `MatLib` 和 `Toon.shader`，结果画面是「卡通光照 + 写实噪点墙面 + 方块树」，
比原版更难看。**着色器和贴图必须同时换**。

### 坑 2：`_ToonAmbient` 必须是绝对亮度，不能从 `ambSky/ambGnd` 推导

这两个值已经乘过 `ambI`，再 Lerp 会算出一个偏亮的灰蓝，夜景变成「蓝色白天」。
正确做法是给固定的绝对色值：白天 `(0.38,0.42,0.55)`、夜里 `(0.10,0.13,0.27)`。

### 坑 3：夜景发灰的真凶是泛光，不是环境光

调了三轮环境光都没压下去，因为**泛光把路面整个抬起来了**。
卡通夜景的正确配方：泛光降到 0.12、**阈值升到 1.35**（只有真正的灯/窗才泛光）、曝光 0.78。

### 坑 4：贴图尺寸改了但绘制坐标没改 → 只画了左下角

`Road()` 原本 `new Px(64,64)` 却按 256 坐标绘制，改成 256 画布后只填满 1/16，
路面出现巨型格子。**改贴图尺寸必须同时检查绘制坐标范围**。

### 坑 5：`SHADOW_COORDS` 不能放在 `CGINCLUDE` 里

它依赖各 pass 的编译关键字。改用 `UNITY_SHADOW_COORDS` / `UNITY_TRANSFER_SHADOW` /
`UNITY_SHADOW_ATTENUATION` 这一组。

### 坑 6：`Campus.exe` 的 mtime 构建后不变

启动器不重链接。判断构建是否生效要看 `Campus_Data/Managed/Assembly-CSharp.dll` 的 mtime。

### 坑 7：室内任何一间抛异常 → 13 间全废

`InteriorBuilder.Build()` 是一次建全部房间的。某一间抛异常会让 `InteriorManager.Init` 抛出，
`-indoor` **静默失效**（人站在广场上，日志只有一行不显眼的异常）。
**最终验收要确认 Player.log 里 `校验完成` 有 13 行**，比截图可靠。

### ⭐ 一条可复用判据：R/G 双通道截断会抹平色相

本轮调人物肤色踩到的最深一个坑，值得单独记：

**现象**：六人脸颊采样全是 `(255,255,23x)`，`R−G = 0` —— 暖肤调彻底消失，脸像过曝照片。

**误判**：第一反应是「自发光太强」。但降自发光（0.085→0.050）几乎没效果。

**根因**：皮肤 albedo `#ffead8` 的 **R 通道本身就是 255（满值）**。
卡通渲染的亮面是 `albedo × 太阳(1.15) × ramp + 环境光 + 边缘光`，**直接相加**，
所以 R 一乘就顶格；同时 G/B 也被推过 255 一起截断 → 三通道全满 → 色相被抹平。

**判据**：

> 肤色/高明度部件是否过曝，看 **`R−G ≥ 10` 且 `G ≤ 245`**。
> **R 顶到 255 本身不是问题，关键是 G 不能顶格** —— R、G 同时到 255 时色相必然丢失。

**修法**：把 albedo 本身压下来（`#ffead8` → `#e0cab6`，R=224 留 31 的余量），
而不是降自发光（自发光把三通道**一起**推高，只会让 G 更早顶格）。

这条对后续所有高明度部件都适用：白衬衫、白围裙、白手套、白发。
**卡通渲染比写实渲染更容易触发这个坑**，因为它的亮面是直接相加、容易过 1.0。
