# 127 · 六人 PMX/VMD 实装与整章剧情节点

2026-11-15。要求：接入 MMD 改进，剧情不反复弹目录，以章节为节点。

## MMD 实装

选用 Unity MMD Tools 0.5.1（UMT，Unity 2022.3+，MIT），本地嵌入 `Game/Packages/com.candidumgames.unitymmdtools`，依赖由 Packages manifest/lock 固定。来源：https://github.com/CandidumGames/UnityMMDTools 。未把 Minecraft 的 Java/JNI/OpenGL 搬进 Unity。

六人的现有精修方块造型通过 `MmdCharacterBake.BakeBatch` 输出真实 PMX 2.0 与 idle/walk/run VMD，再经 UMT 的 PMXScriptedImporter / VMD 转换器导入，生成蒙皮网格、控制器和角色 prefab。活动源/生成资源均在 `Resources/MMD/{id}/`，不是给旧模型加一个 MMD 标签。保留现有像素脸贴图、服装材质并以 importer remap 对应；六人材质组分别 17/14/12/13/14/14。

短发角色 6 骨骼，长发角色另加 11 个独立发束骨骼共 17；长发 VMD 增加幅度受控的待机/行走/跑步摆动。MmdActor 播放 Animator 中实际由 VMD 转换的动画，0.16 秒混合；PlayerAvatar 默认先加载 MMD prefab，缺少时回退方块生成器。换角与第一人称隐藏逻辑保留。`-legacyavatar` 显式验收旧路径；离线导出用 AuthoringLegacy 防止再次导出时误读新 prefab。

原六人目前是 BDEF1 刚性分件蒙皮和 FK 动作，长发摆动是 VMD 动作，不冒称真实物理；不包含视频中完整二次元人物的脸部雕刻、口型/眨眼或新服装资产。UMT 已具备导入外部 PMX、VMD、顶点表情、IK、SDEF 和刚体物理的能力，未来授权素材可走同一导入流程；本轮六人不需要 IK/物理，烘焙 FK 后关闭这六个 prefab 的 TransformManager，避免重复求解。

主 LICENSE 和第三方声明随 Windows 包的 StreamingAssets/ThirdParty 一并分发。没有采用视频角色或未知授权动作，六人 PMX/VMD 从本项目原创模型/动作生成。

## 剧情章节点

DialogueManager.Advance 只在章节变化时暂停。章内场景或地点变化继续播放；章末保存下一章开头进度，返回探索，不自动打开任务目录。任务 HUD 标题改为章节名，RouteLine 固定读取本章第一个真实场景作为章节入口，避免任务地点随章内台词跳动。目录/任务手记仍可手动打开，下一章仍可主动前往并开始，不会自动连播到全卷末。

保留存档行号，因此章内手动暂停/存读档可以继续原句。未改动剧本源。第一卷结束依然是 Finished，入口不会越界。

## 验证

`shots/127-mmd/` 保存导出、构建、截图与运行日志。`-avatarcheck` 额外比较两个 VMD 时间点的实际 BakeMesh 顶点，要求存在变形且无 NaN，验证 PMX 蒙皮/骨骼/材质、六人切换和隐藏重建。CheckTravelBoundary 升级为逐句检查全部八章：章内必须持续 Active，章末必须暂停且 TrackingOpen=false；继续跑原来的存读档、主线传送、支线与完成后入口检查。

质量边界：本轮是 MMD 运行链路与原角色动作改进，不是完整 MMD 美少女资产重做；不保证任意外部 PMX 2.1 专属功能。Windows 为本轮验证目标，WebGL 另行构建验证。未提交、未推送。
