# 产品定义 v0.1（待用户评审定稿）

## 一、定位（用户拍板：2026-10-12）

- 命题方向：官方方向 10「智能游戏原型与交互式叙事工坊」
- 定位：**纯娱乐叙事游戏**
- 题材：**校园 × 恋爱 × 悬疑 × 奇幻**
- 一句话：白天经营日程、夜晚推进剧情，LLM 动态事件导演为每位玩家生成不重样的校园生活与悬疑推进

> ⚠️ 价值风险与对策（对应评分 25%「解题有效性与实用价值」）：
> 「纯娱乐」有被判「玩具项目」的天然风险。对策（**不改定位，只强化**）：
> 1. 剧情与机制扎根真实校园议题（选课 / 社团 / 人际 / 学业压力 / 心理），让评委有共鸣；
> 2. 「重玩不重样 + 结局成长档案」构成完整产品闭环，而非一次性 demo；
> 3. 技术文档中把价值论证写扎实（叙事体验 / 情绪价值 + 方向 10 命题契合度）。

## 二、核心玩法：双循环（用户拍板）

**白天 · 日程经营**（星露谷式）

- 时段：上午 / 下午 / 晚上；资源：体力
- 行动：上课 / 自习 / 社团活动 / 打工 / 运动 / 休息 / 找角色聊天
- 五维数值：体力 / 学业 / 社交 / 心情（+ 每位角色好感度、线索簿）

**夜晚 · 剧情推进**（galgame 式）

- 触发当日/周末剧情事件：对话选择、好感度变化、线索获得
- 章末「导演结算」：回顾本周状态，埋设伏笔

## 三、AI 机制：LLM 动态事件导演（用户拍板，创新性 20% 主力）

- 每日结算时，事件导演读取：日期 / 时段 / 五维 / 好感度 / 已触发事件 ID / 未解线索 + 剧情圣经摘要（角色卡、世界规则、硬约束）
- 输出**结构化 JSON 事件包**（类型 / 标题 / 台词 / 选项 / 数值影响 / 线索），由**确定性事件引擎校验后执行**（字段白名单、数值钳制、防越权改状态）——**LLM 只生成内容，工程层做意图控制**（技术文档核心章节）
- **导演日志 UI**：把「导演正在根据你的状态生成今日事件」的过程流式可视化（对应 UX 分项：流式 / 思考可视化）
- **演示模式降级**：无 API Key 或请求失败时自动切换内置规则事件池——评审/复现零依赖（对应 25% 复现分）

## 四、剧情（待用户选定种子或自创，见 `docs/04-剧情圣经-模板.md`）

- 种子 A《昨日重现》：图书馆借阅记录出现"明天"的日期，主角每天能"重演"前一日并改变一个小事实
- 种子 B《第七位成员》：六人社团的合照里永远有第七个模糊身影，"它"只对新加入的主角说话
- 种子 C《许愿池的债》：旧校舍许愿池有求必应，代价是"记忆"；主角许过愿却忘了内容

## 五、技术栈建议（可议）

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Vite + React | AI 生态最优、迭代快 |
| 2.5D 渲染 | Three.js（react-three-fiber）+ **HD-2D 风格**：3D 像素化场景 + 像素精灵角色 | 低分辨率渲染目标 + 最近邻放大 = 复古像素 3D 质感；同时满足「2.5D 建模」与「星露谷像素风」 |
| 状态与逻辑 | Zustand + 纯逻辑事件引擎（可单元测试） | 工程分：逻辑与渲染解耦 |
| 存档 | IndexedDB（localStorage 兜底），无后端依赖 | 保证零依赖复现 |
| LLM | OpenAI 兼容接口（DeepSeek 等），强制 JSON 输出 | 演示模式兜底；换模型零改动 |
| 部署 | 静态托管 | 评审在线可玩 |
| 美术 | AI 生成像素素材（记录工具+Prompt）+ 程序化 3D 场景 | 原创留痕；第三方素材必须声明许可 |

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 5 周工期 + 美术量大 | 砍功能不砍闭环：先跑通"一天循环"，再横向扩内容 |
| 3D 角色建模难 | HD-2D 路线：角色用像素精灵立绘，场景用程序化低模 + 像素贴图 |
| LLM 生成不稳定 | JSON Schema 校验 + 规则事件池兜底 + 导演日志可回放 |
| 「纯娱乐」价值分风险 | 见文首三项对策 |

## 游戏模式定位（2026-10-14 作者确认）

- **主线推进剧情**：以章节制叙事为主线（承接《剧情圣经》章节地图），玩家主动推进关键剧情节点。
- **支线为日常**：日程经营（白天学习 / 社交 / 探索等日常行动与属性成长）作为支线系统承载日常体验。
- **玩家自选**：主线与支线不强制绑定推进顺序——玩家可自由选择当天推进主线还是经营日常（日程系统提供两类行动入口）。
- 对后续迭代的影响：日程系统（迭代 2）需支持"主线行动 + 日常行动"两类入口；剧情对话系统（迭代 3）需支持章节推进与玩家选项。
