## 四、世界侧：改之前必须知道的

1. **`TownData.BOUND = 150f` 是一根线**：圆形世界半径、林带半径、小地图半径、玩家夹取全部由它推导。
   改大它要同时检查边界植被规则（要求 `r ≥ BOUND-14`，docs/87 里树带半径从硬编码 116~122 改成了
   `BOUND - 12 + rnd*6`，别再写死）。
2. **`BuildingDef.face` 语义**：`±1` = 面向 ±Z，`±2` = 面向 ±X。⚠ `face=±2` 时校验器里的
   `HalfWX/HalfWZ` 是**互换**的——西侧那排房子实际是 Z 向 4m、X 向 3.5m，按直觉算净距会误判。
3. **世界数据不是源码里那份**：`Build()` 末尾有一串后处理（让开车行道外推 0.8m、正门 2.8m 内删灯、
   3m 最小间距去重、植被净距剔除）。**要看真实结果必须 `DumpTownJsonBatch` 导出后再算**，
   读源码点位表会得出错误结论（docs/88 就是这么发现"补的灯被吃掉"的）。
4. **路灯手臂方向**：灯杆模型的手臂沿**局部 +X**，所以世界方向 = `(cos r, −sin r)`。
   南北向路：西侧 `r=0`、东侧 `r=π`；东西向路：北侧 `r=−π/2`、南侧 `r=+π/2`。
   docs/88 在末尾加了统一"对灯臂"pass，凡落在街肩线（半路宽 + 0.8m，容差 0.6m）上的灯按所在街重算，
   所以**改路宽/灯位不用再手改 r**；但脱离街肩的灯（滨河、公园、广场）仍按字面 r 走。
5. **路灯间距规范**（CJJ45-2015，docs/87~88 采用）：6m 杆居住区/人行 15~18m、8m 杆 20~24m、
   支路 15~25m、灯杆距缘石 0.5~1.0m（本项目 0.8m）。有意不装灯的：夏日祭参道与神社石阶（石灯笼 +
   提灯串）、桥面（桥头两侧照明）。
6. **建筑四条净距规则**（`TownBatch`）：建筑↔道路 ≥1m、↔步道 ≥1m、↔建筑 ≥0.5m、↔河道小镇段 ≥8m
   （校园北侧临河带豁免为 2m）。正门接驳段在门前走廊内不计违规。

## 五、室内侧：改之前必须知道的

1. **碰撞是 2D AABB + 楼层掩码，每个实体四周有 0.32m 垫**，且**没有高度层**。
   后果：椅子/桌子四周实际是不可进入的，"坐下"目前做不到；也是 docs/86 跳跃/蹲下被作者否掉的根因。
   楼梯两侧必须有挡墙，否则侧面走出去会瞬间跳层。
2. **朝向约定**（踩过 13 个房间，别再错）：`TextMesh` 在 `ry=0` 时面向 −Z；`Chair` 的靠背在局部 −Z，
   所以 `ry=0` = 坐者面向 +Z。桌子在南 → `ry=0`，在北 → `180`，在西 → `90`，在东 → `270`。
   `Sofa`/`Picture`/`WallClock` 同理。
3. **接顶用 `_ceilY`**：`CeilingSlab()` 会记吊顶高度，`HangRods(p,x,top,z,w,ceil=0)` 按它算吊杆长度，
   `MAX_ROD = 2.8`。不要再写死 0.7m 吊杆。门楣低的房间（礼堂后侧三块牌）要显式传 `ceil`（4.0f），
   否则自动抬升会把牌子顶进门楣。
4. **作者说的"虚影"是三类**，排查时按共用生成函数整体修，不要只改报出来的那一处：
   共面闪面（同材质两面 z-fighting）、悬空薄板（杆没接顶 / 牌浮在台面上）、同尺寸双件叠影。
   对策统一是**错开 ≥2cm** 或**让外框凸出**（展示柜最终做法：整柜实体 + 外凸上下框 + 两条深色隔板）。
5. **门洞坐标规则**：墙号 0/1（沿 X）用世界 X；墙号 2/3（沿 Z）用世界 Z，**不要加 ox**。
6. **能进的 13 间**：`home school library restaurant supermarket canteen dorm auditorium labs
   milktea photo book conv`（`InteriorManager.ToId` 按**交互点名字**映射，改建筑名会静默断掉入口）。
