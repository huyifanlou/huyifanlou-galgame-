## 二、做了什么

### 1. 新增三个共用入口（`InteriorBuilder.cs`）

**(a) `PartC()` —— 卡通倒角盒**

卡通渲染要「大块面 + 硬边」。主家具如果就是一个立方体，外轮廓只有一圈方角描边，明暗 ramp 也
只有一个台阶，看上去像贴纸。倒角后每个转角多出一条 45° 窄面，会吃到相邻的第三个光照台阶，
边缘立刻「硬」起来 —— 这是 cel shading 里最省成本的体积做法。

实现：`ChamferMesh()` 生成 6 主面 + 12 条棱面 + 8 个角三角形（共 26 个凸多边形）。三个要点：

- **绕序不手写**：按外向法线用 `Vector3.Dot(Cross(...), n) < 0` 自动修正。写错也不会出黑面。
- **UV 按法线主轴投影**：每个面的像素密度与 `MeshFactory.BoxUV` 一致，不会拉花。
- **网格按 尺寸+倒角+贴图米数 缓存**：13 间室内上千个部件，重复尺寸极多，缓存后网格数可控。

`PartC` 的位置/尺寸语义与 `Part` **完全一致**（同一套坐标），所以是纯替换，不牵动任何摆放逻辑。
碰撞仍走原来的 AABB（`PartC` 不注册 Solid，Solid 由调用点各自 `Reg`），**走位完全不受影响**。

**(b) `CB()` / `OutlineMat()` —— 按尺寸自动收描边**

`MatLib.LitColorBold()` 默认 0.0055 描边。Lead 这轮给描边 pass 加了距离淡出
（18m 内满强度、55m 外淡出），室内近距离家具描边会很清晰 —— 于是**小物件全用 Bold 会太脏**：
0.06m 的细杆配 0.0055 描边，黑色会吃掉杆本身。

所以 `OutlineMat(hex, minDim)` 按部件最小尺寸分四档：

| 最小边 | 描边宽度 | 典型部件 |
|---|---|---|
| ≥ 0.30m | 0.0055 | 桌/柜/床/沙发/台面（主要家具） |
| ≥ 0.14m | 0.0042 | 椅背、柜门、坐垫 |
| ≥ 0.06m | 0.0032 | 压条、把手、桌腿 |
| < 0.06m | 0.0024 | 细杆、门缝条、挂钩 |

`Part()` 与 `PartC()` 都会自动套这一层，**调用点不用关心描边**。
带贴图的材质（墙纸/地砖/木纹）原样返回 —— 它们的 `_Color` 是白色，按颜色重建会丢贴图。

**(c) `Darker(mat, k)` —— 同材质暗一档**

卡通分件（台面托边、靠背压条、柜门缝）需要同色系暗面。直接新开调色板会让配色失控，
所以从已有材质派生：`new Material(src) { color = src.color * k }`。按材质缓存。

**(d) `InteriorWood()` —— 室内木作统一平涂**

`TextureLibrary` 的 `wood` 是 `#a1887f` 的灰褐木纹。写实风格下没问题，但卡通渲染的冷调暗面
（`_ShadowTint` 偏紫）会把它压成脏褐，家具在画面里就「消失」了。室内家具量小、离镜头近，
改成高饱和平涂色 `#f5c26a` + 粗描边更符合卡通语言。**大面积的墙纸/地砖/天花仍然走贴图**
（保持墙面细节），世界侧的木头不受影响（WorldBuilder 直接调 MatLib）。

### 4. 墙面装饰补细节

- **挂画**：外框倒角 + 卡纸 + **三块色块**（原来只有两块灰绿块，远看像两块脏玻璃）
- **挂钟**：倒角表盘 + 外圈橙色环（比表盘大 3cm，卡通描边把钟从墙纸上「抠」出来）+ 橙色中心点
- **绿植**：盆体倒角 + 盆口压条 + **双层叶簇**（错开高度与半径，双色叶团比单球有体积）
- **窗**：边框倒角 + **窗台**（比框外凸 4cm，卡通渲染里这条亮面把窗从墙上「托」出来）
- **吸顶灯**：发光盘 + 一圈外框（外框比灯盘大 6cm）
- **公告栏**：外框凸出 + 内白板 + **三块彩色小贴纸**（56m 走廊墙面有节奏）
- **菜单屏**：三行彩色菜名条（原来就是一块墨绿板）
- **工具墙**：外框倒角 + 白板面 + 高饱和四色工具挂块

## 三、为什么这么做（而不是别的方案）

1. **不新增材质入口，只新增「尺寸感知」的描边收窄**。Lead 已经定了 `LitColorBold` 的语义，
   室内只是在它外面加一层按尺寸的适配 —— 不改变美术语言，只避免小物件被描边吃掉。
2. **倒角而不是加细节模型**。13 间室内上千个部件，每个都手工分件不现实；倒角盒是
   「同一套坐标、纯替换」的方案，改动最小、收益最大（每个转角多一个光照台阶）。
3. **不改碰撞**。`PartC` 不注册 Solid，`Solid` 仍由原调用点 `Reg`，AABB 与楼层掩码逻辑一行没动。
   这是 docs/89 第五节的硬约定（碰撞是自写 AABB，不是物理引擎）。
4. **不改门洞坐标规则、不改 `HangRods` 接顶逻辑、不改朝向约定**。所有摆放坐标原样保留，
   只改材质与网格。因此 `Validate()` 的 13 间碰撞盒数量与问题数都不受影响。

## 五、踩坑

### 1. 负数取模导致 `IndexOutOfRangeException`，整个室内系统静默失效

给走廊公告栏加彩色贴纸时写的是：

```csharp
C(new[] { "#ffd88a", "#a8e0f0", "#ffb0b0" }[(Mathf.RoundToInt(dx) + i + 9) % 3])
```

`dx` 有负值（`-24f`、`-15.6f`、`-7.2f`），而 **C# 对负数取模返回负数**
（`(-24 + 9) % 3 == -3`），数组直接越界。

后果不是「公告栏没画出来」，而是 `InteriorBuilder.School` 抛异常 → `InteriorBuilder.Build`
中断 → `InteriorManager.Init` 抛出 → **整个 `-indoor` 失效**。表现是：截图里人站在钟楼广场，
`-indoor milktea` 完全没进室内，而且日志里只有一行 `IndexOutOfRangeException`，很容易误判成
「参数写错了 / exe 是旧构建」。

修复：索引改用非负种子 `int seed = Mathf.Abs(Mathf.RoundToInt(dx * 10f)) / 3;`。

**教训**：室内是「一次 Build 全部房间」，任何一间抛异常会让 13 间全部失效，且错误信息在
Player.log 里不显眼。改完必须确认日志里 `校验完成` 有 13 行。

### 2. `Campus.exe` 时间戳不变 ≠ 构建没生效

构建成功后 `Game/Build/Win/Campus.exe` 的 mtime 仍是旧的（启动器没重新链接），
真正要看的 `Game/Build/Win/Campus_Data/Managed/Assembly-CSharp.dll` 的 mtime。
截图前先核对这个，别被 exe 时间戳误导。

### 3. 截图落点可能卡进家具/墙体

`-px/-pz` 是硬塞坐标，不检查碰撞。落点如果在家具里，画面会是纯黑（相机在几何体内部）。
奶茶店我第一次给 `(1900, 6)` 正好落在吧台里，三张全是黑屏。
对策：先用默认出生点（不传 `-px/-pz`）拍一张确认能进，再按平面图挑落点。

## 六、遗留

1. **椅子仍坐不进去** —— docs/89 第七节的开放项，需要「坐点」或给碰撞加高度层，本轮未动。
2. **倒角网格数量**：`ChamferMesh` 按尺寸缓存，但 13 间室内尺寸组合多，最终网格数比原来多。
   目前构建产物仍 99MB、实机未见卡顿，若后续加室内再关注。
3. **`InteriorWood()` 是室内专用平涂**：世界侧木作仍走 `wood` 贴图，两处观感会略有差异。
   如果作者觉得不统一，可以在 Lead 那侧把 `wood` 贴图本身改成高饱和版本，然后室内回退到 `T("wood")`。
