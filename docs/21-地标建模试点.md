# 21 · 地标建模试点：神社 / 钟楼 / 骑楼

作者确认按“混合管线”推进：地形、水、路网继续程序化，视觉焦点换成真正的几何构造。
本机没有 Blender，因此这一轮先走计划里的第 1 条——**用 C# 程序化网格做“建模”**，验证“几何替代贴图盒体”的管线与效果；
后续装 Blender 或引入 CC0 模型时，可直接把 FBX 换成对应节点，不影响世界数据。

## 一、本轮三件试点

### 1. 神社本殿 / 拜殿（新样式 `shrine`）
- 石基坛 + 木地板 + 正面三级踏步
- 6 柱柱网、背墙/侧墙、正面障子（复用日式立面贴图）、中央门
- 楣梁 + 一排斗栱、深出檐双坡瓦顶（出檐 1.5m）、山墙端封、椽头、脊端金饰
- 正面注连绳 + 四条纸垂
- `BuildingDef.style` 新增 `shrine`，数据里本殿/拜殿各改一行即生效；碰撞仍是整栋 BoxCollider

### 2. 钟楼（替换原来的方盒 + 四棱锥）
- 基座（带拱门）、四棱台收分塔身（新增 `MeshFactory.TaperedBox`）、钟楼层、小阳台栏杆
- 四面钟面、檐口、四棱锥顶、避雷针/风向标
- 总高约 19m，成为主街北端的视觉焦点

### 3. 骑楼老街（6 间店铺）
- 店铺前加连续柱廊：柱列 + 二层挑廊板 + 挑檐小瓦顶 + 栏杆
- 檐下挂灯笼与招牌
- 覆盖绸缎庄、茶楼、杂货铺、药铺、邮局、戏院；数据不变，渲染时按 id 追加

## 三、性能与后续优化（按优先级）

1. **静态合批 + GPU Instancing**：柱、栏杆、斗栱、椽头这类重复小件目前是独立物体；下一步按材质合并或换成 InstancedMesh，预计整镇 draw call 可降一个量级。
2. **LOD**：钟楼/神社做 2–3 级 LOD，远景只保留剪影；树与路灯用公告板远景。
3. **碰撞简化**：地标用 Box/Convex 组合，不要用渲染网格做 MeshCollider（目前建筑已是 Box）。
4. **贴图图集**：桥石/屋面/木纹/混凝土合并成 trim sheet，减少材质切换。
5. **外部模型接入**：装 Blender 后可用 bpy 脚本生成模块化套件并导出 FBX；或直接导入 CC0 低模资产，替换 `ShrineHall/ClockTower` 等节点即可。
