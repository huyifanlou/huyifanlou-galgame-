# 10 · 贴地纹理密度收尾：球场 / 花坛 / 土斑 / 中线石带（2026-10-16）

接 `docs/09`（主路石板 4×4 + 别墅/操场/池塘 ×2）。本轮把「密度铁律」里**剩下的贴地纹理一次推到基准 160px/米**
（撞 2048 上限的降到极限为止），并把能到位的都纳入校验器**强制**范围。

## 做了什么

| 贴图 | 覆盖米数 | 之前 | 现在 | 密度变化 |
| --- | --- | --- | --- | --- |
| 花坛 `flower` | 1.7×1.7 | 64×64 | **256×256**（S=4） | 37.6 → **150.6**（基准 ±6% 内） |
| 土斑 `dirt` | 4.8×4.8 | 96×96 | **768×768**（S=8） | 20.0 → **160.0**（精确） |
| 中线石带 `roadband_v/h` | 0.6×1 | 8×32 / 32×8（拉伸版，横纵不等密度） | **96×160 / 160×96**（按世界尺度重画） | 13.3×32 → **160×160** |
| 篮球场/网球场 `court_*` | 15×9 / 15×8 | 512×320 | **2048×1280**（S=4） | 34~40 → 136.5×142~160（**撞 2048 上限**） |
| 操场跑道 `track` | 16×10 | 1024×640 | **2048×1280**（S=4） | 64 → 128（撞上限） |
| 池塘 `pond` | 7.2×7.2 | 512×512 | **1024×1024**（S=4） | 71 → 142 |

> `track`/`pond` 不在点名清单里，但同属「贴地大面 + 受 2048 限制」一类，顺手一起推到上限，免得下次又差一档。

## 实现要点

- 前五项全部只改 `Px` 的密度倍数 `S`：绘制代码（逻辑坐标 = 世界尺度配方）**逐字未动** → 世界观感不变、只是更清晰。
- **中线石带是唯一需要重画的**：旧版 8×32 贴在 0.6×1m 上时横纵密度天然不等（13.3 vs 32 px/米），
  任何整数 `S` 都无法同时对齐两轴 → 改为按世界尺度画 96×160（= 0.6m×1m @160px/米），
  边线 **7.5cm**、接缝 **3.1cm** 的世界宽度与旧版一致（= 12px / 5px）。
  同时把 mesh 纵向平铺从「`round(len/1)` 次」改成精确 `len` 次（1 铺/米），接缝间距从此严格 1m。
- 校验器「基准组」扩容为 `grass / path / road_mainstone / road_cobble / flower / dirt / roadband_v / roadband_h`
  —— 这些必须落在 160px/米 ±6%，否则报错；`track / court_* / pond / villa` 仍是登记项（受 2048 上限，要再升必须分块）。

## 踩坑

- **`git checkout <ref> -- <文件>` 会连工作区的未提交改动一起冲掉**（本轮真踩到）：为了导「初版」贴图做贴图级对比，
  先 `checkout HEAD~1` 取旧代码、导完再 `checkout HEAD` 还原 —— 但 `HEAD` 是**上一轮**的提交，
  于是本轮刚改好的 6 处 `TextureLibrary` 内容被一并还原掉。
  发现后按原样重贴，并用两条机器验证证明恢复无损：
  ① 重新导出全部贴图与改动前的备份 **逐字节比对（20/20 一致）**；② 重建播放器，`Assembly-CSharp.dll` 的 md5 与改动前构建一致。
  **下次的规矩：动到「临时回退某文件」之前，先确保改动已经在 git 里（提交或 stash）**；
  或者干脆先把改动提交，再回退取旧版 —— 反正随时能 `git checkout HEAD -- <文件>` 拿回来。
